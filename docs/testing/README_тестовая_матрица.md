# Тестовая матрица должностей и ролей — МиниСЭД

Чтобы вручную прогнать все функции МиниСЭД, нужно завести тестовых пользователей и раздать роли.
Заполните два файла (открываются в Excel/Google Sheets, разделитель — точка с запятой `;`, кодировка UTF‑8):

1. **`1_Пользователи_и_роли.csv`** — сотрудники, их данные и роли доступа в системе.
2. **`2_Назначение_маршрутных_ролей.csv`** — кто исполняет каждую роль в маршруте согласования заявок.

> ⚠️ Обязательное: у каждого тестового пользователя должны быть **Bitrix ID** и **Email**.
> Вся идентификация в системе завязана на Bitrix ID, а на Email дублируются уведомления.
> Один человек может иметь несколько ролей (например, «Инициатор» + «Юрист»).

---

## Файл 1 — роли доступа

| Роль | Что даёт | Сколько нужно для теста |
|---|---|---|
| **Инициатор** | Создаёт согласования (светофор) и регламентные заявки, отслеживает свои | минимум **1** (лучше без прав юриста) |
| **Согласующий** | Может согласовывать / отклонять / возвращать на доработку | 1–2 |
| **Юрист** | Видит раздел «Работа юристов», берёт заявки в работу и исполняет; согласовывает этап «Юридический отдел» | минимум **2** |
| **Руководитель юрслужбы** | Как юрист + смена маршрута | по желанию, 1 |
| **Администратор** | Полный доступ, управление пользователями и справочниками (админка) | 1 (можно вы сами) |

> **Про этап «Юридический отдел»:** он **групповой** — падает сразу **всем** юристам, и согласовать может **любой** из них.
> Поэтому для проверки этой фишки нужно **минимум 2 юриста**. Отдельно назначать юротдел в маршруте (файл 2) **не нужно**.

---

## Файл 2 — маршрут согласования заявок

Маршрут регламентной заявки (доверенность/МЧД) строится **автоматически**. Часть ролей — всегда, часть — по категории ЦФО / проекту.
Для каждой роли укажите исполнителя (**Bitrix ID**). Если исполнитель не назначен — при отправке инициатор выберет его вручную.

**Всегда в маршруте:** Руководитель ЦФО → Финансовый директор → Юридический отдел (групповой) → Финальный подписант / ген. директор.

**Добавляются по категории ЦФО / проекту:**

| Категория ЦФО / условие | Добавляется роль |
|---|---|
| Отдел продаж | Руководитель отдела продаж |
| Управление доходами / Маркетинг / Бронирование | Коммерческий директор |
| Бухгалтерия | Главный бухгалтер УК |
| КДП / Подбор / Обучение (HR) | Руководитель отдела по работе с персоналом |
| ИТС / ИТ | Технический директор + Операционный директор |
| СГХ / Территория / Склад | Операционный директор |
| Ресторанная служба **или** проект «Невесомость» | Директор ресторанной службы |

## Минимальный набор для проверки ВСЕХ фишек (~5–7 человек)

- **1 инициатор** (без прав юриста) — создание согласований и заявок, отмена/удаление, «Получил/ознакомился».
- **2 юриста** — раздел «Работа юристов» (Новые/В работе/Архив), групповой юрэтап «любой юрист», исполнение заявки.
- **по 1 человеку** на всегда‑роли: **Руководитель ЦФО**, **Финансовый директор**, **Финальный подписант**.
- *(по желанию)* люди на условные роли (Руководитель продаж, Коммерческий директор, Главбух, Технический/Операционный директор, Директор ресторана) — чтобы проверить условную маршрутизацию по категориям ЦФО.
- **1 администратор** — может совпадать с вами.

Люди переиспользуются: один и тот же человек может быть и инициатором, и согласующим, и исполнять маршрутную роль.

---

## Что этим проверяется (чек‑лист)

- Согласования (светофор): создание, участники из Битрикса, документы, круги, повторный круг, лист согласования, отмена/удаление.
- Регламентные заявки: анкета доверенности/МЧД, приложение файлов, валидация полей и срока ≤ 3 лет.
- Согласование заявок в общем списке «Требует действия», выбор согласующих по ФИО.
- Групповой этап «Юридический отдел» — падает всем юристам, любой согласовывает.
- Раздел «Работа юристов»: Новые → В работе → Архив, взятие в работу, исполнение, «Скачать доверенность».
- Закрытие заявки только инициатором («Получил/ознакомился»).
- Уведомления в Битрикс (колокольчик) + дубли на почту на каждом переходе.
